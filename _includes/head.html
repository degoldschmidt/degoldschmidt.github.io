Fira Sans keeps 400 and 600; 600 is the display weight for titles and labels. {%- endcomment -%} <link rel="preconnect" href="https://fonts.googleapis.com" /> <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin /> <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Fira+Sans:wght@400;600&family=Lato:wght@400&display=swap" /> {%- comment -%} Cache-busted on build time. Without this the stylesheet is one URL forever, so a browser that cached it keeps using the old one — which is how a layout change appeared to have no effect locally while the server was serving the new file correctly. It matters more in the field than in development: a visitor who scans the QR code, gets a version of the site, and comes back after an update would otherwise be served the stale stylesheet against fresh HTML. `site.time` is the build timestamp, so the URL changes only when the site is rebuilt, not on every request. Same treatment for the simulation, which has the same problem and is worse to debug. {%- endcomment -%} {%- assign v = site.time | date: "%s" -%} <link rel="stylesheet" href="{{ '/css/main.css' | relative_url }}?v={{ v }}" /> {%- comment -%} Favicon set, replacing a 460x460 portrait JPEG that was illegible at 16px and gave iOS "Add to Home Screen" nothing to work with. {%- endcomment -%} <link rel="icon" href="{{ '/favicon.ico' | relative_url }}" sizes="32x32" /> <link rel="icon" href="{{ '/assets/icon.svg' | relative_url }}" type="image/svg+xml" /> <link rel="apple-touch-icon" href="{{ '/assets/apple-touch-icon.png' | relative_url }}" /> <link rel="manifest" href="{{ '/site.webmanifest' | relative_url }}" /> <meta name="theme-color" content="#6e377a" /> {%- comment -%} jekyll-feed generates /feed.xml but does not advertise it; without this the feed is unreachable from the site. {%- endcomment -%} {% feed_meta %} {%- comment -%} Search opt-out, off by default.
